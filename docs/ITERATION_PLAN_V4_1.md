## 1. 当前判断

问道·灵契已具备可运行的离线修仙骨架：两种修炼路线、六流派配装、真实战斗与生产、六卷多幕主线、十八支线、闭关备料、天门和三阶仙界。对齐审计证明它已超过“直接点选项领奖”的原状态，也发现了原验收遗漏的存档风险、反馈缺口和美术错配。

**大型、长篇、持续有新选择的修仙体验仍只完成一部分。** 下一步应补能改变玩家行动的故事与系统连接，不能只增加层数、角色名称、对白对象或图片文件。用户允许体量自然增长至七八百 MB 或 1 GB，没有提出强制大小门槛；本方案不以安装字节验收内容，也不为凑体积加入重复资源。

## 3. 下一迭代的原则与实施次序

只开发能够闭合“读到的承诺 → 实际行动 → 人物 / 世界回应 → 下一目标”的内容。每条新链都要具备资源来源、可保存进度、失败 / 返回路径、实际奖励与合适音画。继续使用现有离线架构和原创 NPC 竞技，不凭参考《一念逍遥》就增设真人服务器或 MMO 前置条件。

| 顺序 / 优先级 | 完整交付单元 | 为什么先做 | 完成标准 |
| --- | --- | --- | --- |
| A / P1 | 专属生产计数、只读全文重读、两路线仪式术语、证据札记 | 先让文案说的事等于玩家实际做的事，给后续任务可靠基础 | 本文第 7 节测试通过；旧档不重发、不吞进度；所有完整故事可只读回看 |
| B / P1 | 第一 / 第二卷各一条扩展主路线，守护与求证至少一个不同实际目标 / 后果 | 前期是理解世界和动力最集中的位置，先把爽点与新手心流做好 | 两卷从普通新档无注入完成；动作种类与当前泛用计数有实质差异；两选择都可达后续，不迫使抽卡 |
| C / P1 | 三阶仙界各一条 4～6 幕行动链 | 先补飞升后空白，避免只循环“付费静修—猎场—十层试炼” | 每阶不同主要矛盾、至少一个非“任意赢战”的目标、一次真正世界回应；原进阶成本/胜利独立保存 |
| D / P2 | 第三～六卷扩展、伙伴行动链与跨卷后果 | 在前期及仙界样板验证后展开同一标准 | 六卷用同口径内容/目标清单验收；每卷至少一个新玩法组合或可保存分支后果，避免单纯加对白 |
| E / P2 | 按完整内容包扩展区域与新怪、人物、镜头、音乐 | 美术跟随身份和场景，不反过来用随机素材拼故事 | 每个新资产有 stable ID、语义、裁片、比例、实际引用和旧图处理记录；没有空入口 |
| F / 并行 | 真人心流、设备矩阵、交付恢复 | 发现真实误导 / 等待 / 手机问题，约束前五项 | 第 9～10 节取证；新 APK 与新源码可复核；不能以测试数量宣布体验完美 |

A～F 是待实施和待验收的方案，当前工作树不因本表而自动具备这些功能。不承诺未经样板测算的天数；每完成一个完整单元再提交、体验和校准。

## 5. 任务种类：从泛用计数到具名行动

当前 21 个 `key:id` 主要是某个副本胜场、Boss 胜场和任意炼丹 / 打造，不应称作 21 种玩法。下一批先实现以下六类完整目标；每类至少在一条完整剧情中实际使用，而非仅注册类型。

| 新目标，拟用 ID / 记录方式 | 玩家实际操作 | 失败 / 回退规则 | 验收要点 |
| --- | --- | --- | --- |
| 指定成丹 `pillBatch:heal0` 等 | 研究正确丹方、按指定配方实际成丹 / 收丹 | 缺料提示对应来源；队列开始不算完成；取消如实退款 | 错丹、旧成丹、库存购买/赠送、重复收取都不能抵当前约定；实际制作能完成 |
| 指定器物 `gearForge:set:slot` | 制作约定的套装 / 部位，并可长按实际 UID | 阶位 / 配方材料不足可返源；失败保存不增加计数 | 任意别的装备不抵约定；同身份回收不会撤销已经履行的制作经历 |
| 护送 `escort:route` | 在可见路线上选择前后次序，遭遇战护住具名目标或送达地点 | 失败保留已确认路点，清楚标未完成；重试不重复扣已封存成本 | 不能普通任意副本胜利代替；描述、角色美术、护送条件真实一致 |
| 修复 / 封漏 `siteRepair:siteId` | 看具名损坏点，准备材料并完成一段现场操作 | 尚未提交材料不扣；已提交进度可恢复；无故障损毁珍贵物 | 不以任意打造计数当修复；每个 site 明确产生何种世界状态 |
| 证据核验 `evidenceCheck:caseId` | 从已读原始记录选择相互印证的证据，明确它支持何种行动 | 错误保留已读证据并给可理解提示，不重领资源 | 调查顺序 / 选择至少影响一项可保存证据结果；不能仅强制点完两个热点却称推理玩法 |
| 战术挑战 `combatObjective:ruleId` | 在读条、双目标、护盾 / 净化等实际机制中完成一项明确目标 | 有保底获取 / 替代策略；调配后重试；练习不计正式进度 | 两路线和非指定随机技能都能完成；记录实际战斗事件，不能仅检查战报胜利 |

这些目标设计需要引擎扩展，当前源码没有因为本表而支持护送 / 证据核验等新系统。以 A 阶段生产计数作为最小增量，B 阶段先实现护送与证据的一条样板，再扩展种类。奖励由既有引擎提交，任务模型只读取合法记录，演出不造第二份产出。

## 7. 数据、分支与回看底座

### 7.1 专属制作计数

现在 `stats.crafted` / `stats.forged` 是合法总计，却不足以证明“亲炼指定温药 / 护阵器”。拟新增有上限、稳定目录约束的制作记录，区分**炉次**与**实际产量**：每配方的成丹批次 / 成丹数量、每套装＋部位的实际打造件数。18 配方与六套六部位的键集合有界，不以任意字符串增长存档。

计数只在实际产出动作提交时增加：即时成丹、队列收丹、真实打造。排队、控火中途、库存购买、赠送、免费试玩预置、普通使用、奖励领取和渲染不算亲手制作。控火多出丹可增加产量，却不能把一炉记成两炉。保存失败回滚计数 / 材料 / 物品 / 随机流；提交后渲染失败保留已提交事实。

旧档不反推不存在的配方计数。已经完成篇章保持完成与原奖励；正在执行旧目标的旅程需保留目标版本或兼容规则，避免新要求把它清零 / 反向锁死。新接目标在接取时记录精确计数 baseline，历史制作不直接抵新约定。

必须验证：错配方不计、旧库存不计、批量/额外产量正确、队列只能记一次、取消无进度、不同部位不计、满库存/材料上限、回滚 / 提交后故障、合法旧档与两试玩键隔离。界面同时显示“本次亲炼一炉 / 实得几枚”，与任务标准一致。

### 7.2 选择后果与证据札记

保留 `protect/seek` 与当前道誓 ID，用新增有界 flag 记录具名事件后果、证据和 NPC 见证。早期至少第一/第二卷两选择出现一项不同真实目标和一项后续响应；不以不同一句结尾冒称分支玩法。后续共享主线可以汇合，但札记明确哪些人、记录和现场来自自己的选择。

核心突破材料 / 功法有等值可靠渠道，两选择均可飞升；后果提供战术差异、人物态度、取证方式与可选后续，不用永久缺核心资源强迫选“正确”路线。目标不同产生的经济成本要在合法策略中复算，不能意外使某条路线必须付灵玉或抽卡。

### 7.3 只读全文重读

当前 completed 场景只有摘要，“往事札记”不等于全文重放。下一迭代提供分段阅读：序幕、已读线索、自己选择的回应、各段行动后的对白、归来。回看使用纯展示游标，与经济/任务阶段隔离；不调用 `beginStory/advanceStory/claim*`、不增胜场 / 制作 / 好感 / 奖励、不重播一次性消费。

旧档没有当时选择时，显示“旧记录未保留抉择”，允许明确标记的分支文本查阅；不能把后来手选分支伪装成历史经历。读完、退出、刷新、跨模式、保存失败与重复点返回均不发奖。所有已有全文可以回看后，再扩长篇，避免大量新对白完成后无法再读。

## 8. 音画制作与页面标准

每条新增剧情先列可复用现有资源与缺图，按稳定身份制作：地点、敌物种、人物/表情、器物名字/部位、材质/元素、品级及镜头用途。用生图模型补真实缺口，核验完整原图及原生裁片，再检查实际页面；不以文件命名或 metadata 同名代替看图。

新增故事优先补具有叙事用途的场景与关键镜头：事件前/后状态、具名人物认可、得到传承时的正确器物、不同仙阶世界。地图能合理同区域复用；不同套装装备身份不能共享画格。旧图放相符装备/场景/藏画，不删除、不强绑定错物件、不复制加体积。菜单/说明/数值仍程序绘制，不让生成图承担精确文字。

页面目标为首屏可判断“现在做什么 / 为什么 / 点哪里”，细节进入分页或二级详情。独立战斗仍保护气血、四神通、灵宝、三丹药与命令；独立故事/闭关/仙界保留正文与主按钮。同页操作、奖励返回、配置返回及独立场景退出需明确导航恢复策略，不能把所有返回都当新入口清空原位置。

音场沿现有四曲和效果触发，新增章节有不同听感需要时再作原创配乐；没有用户全对白配音要求，不把所有剧情改成昂贵录音前置。实际音乐播放、后台停播、切场 / 跳过、静音和连续战斗覆盖；压缩参数以听感/资源使用决定，不将大 WAV 填充当沉浸增长。

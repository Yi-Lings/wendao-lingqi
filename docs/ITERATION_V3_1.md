# 灵契 V3.1 自主优化迭代

2026-10-14。在 V3 完整玩法基础上完成一版成长引导、配装决策与操作可靠性增强，交付源码与可并行安装的 Android 测试包。存档继续使用 V3 结构和原有保存键，V1/V2 迁移路径保留。

## 本轮优化方案与实现

| 现有问题 | 实现的改进 | 玩家看到的结果 |
| --- | --- | --- |
| 内容入口多，静态指引没有说明此刻该做什么 | 根据当前主修、修为、试炼与实际资源计算仙途目标 | 首页直接晋级、服丹、开启静修，或跳转到缺失材料的真实秘境 |
| 十层突破需要在多个页面查找条件 | 圆满修为、境界试炼和材料清单放在同一目标内 | 知道还缺多少材料；第六境使用自证试炼与终章目标 |
| 待领取悟道券、章节和委托容易遗漏 | 仙途目标页列出实际可领取、可推进的任务 | 可顺路处理奖励和故事，保留玩家的剧情选择 |
| 一键装配只比较单件属性，忽略整套加成 | 以实际属性计算器评估当前、散件和各套装方案，再做有限次调整 | 推荐方案不会降低整套面板战力；先展示换装和套装变化，再主动应用 |
| 背包难以比较新装备 | 显示换装后的整套战力变化，提供战力收益、品质、获取时间排序 | 更容易辨认有用物品；详情显示攻击、防御、气血等前后差值 |
| 批量分解没有物品和返还预览 | 展示具体 UID 对应物品、数量、实际可容纳的灵石与天道尘 | 确认前不删除；穿戴、锁定、预设、待选洗炼和红装继续受保护 |
| 查看方案之后装备状态可能变化 | 应用时重新核对已预览的换装或分解列表 | 过期方案拒绝提交，需要重新查看 |
| 弹窗刷新易丢失位置，键盘可移到背景 | 锁定背景滚动、保留同一弹窗的滚动与焦点、限制 Tab 范围 | 保护装备后不跳回列表顶部；关闭设置返回原按钮 |
| 战斗每 250ms 替换整块 DOM | 相同内容跳过更新，变化时恢复目标焦点和敌人列表位置 | 暂停状态不再重复重建战斗界面，键盘转火更稳定 |
| 保存失败只有短暂提示，首次开局仍可能进入游戏 | 顶部持续显示保存状态，设置支持重试；首次失败保留年龄入口 | 不产生未保存的新进度；已有有效档可查看和导出；关键操作继续回滚 |

推荐针对**面板战力**，不是所有流派的实战最优解。套装机制、暴击、治疗与技能连携仍需玩家判断，预览会列出激活和失去的套装、道品特效。该有限搜索没有全局最优承诺，经济数值和抽卡规则沿用 V3。

仙途建议通过纯读取计算产生，不消费材料、不推进随机流、不保存额外任务状态。点击旧目标会重新校验目标身份；不再成立时只更新提示，不执行旧操作。静修到达门槛后首页目标自动刷新。

## 验证结果

- **142 / 142 项 Node 逻辑检查**：包含原有 125 项和新增 17 项；新检查覆盖两路线全部 120 个成长节点、十层条件、终境限制、套装收益、过期预览、资源上限、保护规则和原有存档兼容。两路线完整合法操作通关模拟继续通过。
- **46 / 46 项真实浏览器检查**：原有 32 项回归，加新增 14 项。包括新账号真实服丹与晋级、实时目标、来源跳转、换装/分解确认与刷新、原生保存失败回滚、首次保存失败与重试、有效档启动失败恢复、键盘焦点和暂停 DOM 更新。
- 新界面检查 **320、360、390、412、1440** 像素宽度，覆盖减少动态效果模式；无横向溢出。浏览器页面异常、控制台错误、失败请求、HTTP 错误和外部请求为零。
- 在本次 Linux Chromium 环境，满 300 件背包的推荐与排序界面完成读取检查，并记录各自耗时。该数据只描述本次浏览器测试，不代表 Android 低端设备性能。
- **Android Gradle 构建成功**：Java 17、Gradle 8.9、AGP 8.7.3、SDK / build-tools 35。APK 的全部 **24 个 Web 资源与测试源码逐字节一致**；签名校验通过，APK v2 签名有效，没有网络、账户或共享存储权限。

机器报告保存在 `docs/validation/browser-v31-report.json`、`docs/validation/browser-v31-regression-report.json`、`docs/validation/node-v31-all.log` 和 `docs/validation/apk-v31-check.txt`。新界面截图在 `docs/validation/v31/`。浏览器工具从仓库目录解析根路径并自动查找已安装的 Chromium，也支持 `LINGQI_CHROMIUM` 指定外部路径。

## 交付与安装

构建产物：`dist/wendao-lingqi-v3.1-preview.apk`，48,058,917 字节（约 45.8 MiB）。

```text
SHA-256: 3cb7dabc16622346bf9c70a4160ccb2a365f9f7371f6d54d647ae5ed09d5e671
包名: com.lingqi.game.preview
名称: 灵契·测试版
versionCode: 4
versionName: 3.1
最低系统: Android 8.0 / API 26
目标系统: API 35
```

当前环境没有原个人发布私钥，因此交付使用已有调试签名的**独立测试包**，可以与 `com.lingqi.game` 的 V3 共存。它不会自动读取原应用的私有文件；在 V3 设置中导出 JSON，再在测试版导入，即可迁移进度。本轮没有发布或替换 GitHub 的 V3.0 正式 APK。

标准 release 包仍使用 `com.lingqi.game`；保持原签名覆盖安装需要提供原有私钥。`build-android.sh` 的版本已更新至 3.1，但它仍会在原签名缺失时停止，不创建替代发布密钥。

## 复现

```sh
npm test
python3 -m http.server 8787 --bind 127.0.0.1 --directory web
```

准备 `qa-tools` 中的 Playwright、Chromium 和中文字体后，在另一个终端运行：

```sh
npm run test:browser
```

标准 Android 构建和测试包静态审计：

```sh
gradle --no-daemon -p android :app:assembleDebug
python3 audit-apk.py android/app/build/outputs/apk/debug/app-debug.apk --variant debug
```

浏览器集成使用经过完整校验的中后期夹具，不能据此认定全部道具的经济可达性。当前未进行 Android 实体设备安装、系统文件选择器、覆盖升级或连续运行测试；下一轮设备验证应覆盖系统返回、进程恢复、刘海布局和低内存长时间运行。

# V4.8 爽感审计：全系统盘点与取舍

审计日期：2026-10-29。基线：`619c55d`（V4.7 公开发布后）。范围：`web/` 下全部 40 个前端模块、战斗数值、奖励呈现、突破与飞升演出。方法：代码审查（给出文件与行号）、从 `data.js` / `core.js` 实际常量推导成长曲线、逐项核对"爽感"的五个来源。本文记录的是**可验证的呈现事实**，不是玩家情绪测量；没有真人试玩数据，因此不宣称"已经爽"。

## 爽感的五个来源与判定口径

| 来源 | 判定口径 | 本项目现状 |
| --- | --- | --- |
| 打击感 | 每次命中是否有可感知的即时反馈 | 仅妖王 |
| 成长感 | 变强是否能被量化看见 | 面板有战力，战斗内没有 |
| 获得感 | 稀有掉落是否有仪式 | 抽卡有，结算无 |
| 成就爽 | 阶段成果是否被承认 | 首通/三星有，无称号 |
| 叙事爽 | 抉择是否有分量 | 人界强，仙界弱 |

## 发现

### J01 普通敌人完全没有受击反馈 · P0

`app.js:431` 给敌人卡片挂了 `hurt` 类，但 `battle.css:1432` 只为 `.boss-target.hurt` 定义了动画：

```
1432: .boss-stage .enemy-card.boss-target.hurt {
```

普通小怪被打中时，除了血量文本变化没有任何视觉变化。一场普通秘境战斗通常 2–4 个目标、持续数十秒，**手感完全缺失**。

### J02 伤害数字不可见 · P0

`combat.js:55` 把伤害直接扣进 `e.hp`，全程不产生任何数值事件。界面上唯一的数字是 `app.js:430` 的 `当前 / 上限` 文本。会心更隐蔽：`combat.js:57`

```
if(crit)note(b,'会心！'+e.name+'受到 '+Math.round(amount)+' 点伤害');
```

只写进 `b.log`，而战斗记录在 `app.js:441` 是一个默认折叠的 `<details>`。

结果是：`combat.js:46` 里 `clamp(p.crit,0,.65)` 的暴击率与 1.2–2.8 倍暴伤这套核心数值设计，**在默认视图里不存在**。玩家无法感知"这一击很重"。

### J03 会心没有视觉与听觉身份 · P0

除 J02 外，`audio.js:12` 只注册了 `battle-hit`（450ms 节流），没有会心专属音。会心与普通命中在听感上完全相同。

### J04 击杀没有收束 · P1

`combat.js:59` 的处理是 `e.dead=true`、`killCount+1`、写一条日志。敌人卡片随后带上 `dead` 类淡出。没有"最后一击"的强调，也没有溢出伤害（overkill）的表现。

### J05 连击有数据、无呈现 · P1

`combat.js:90` 为五行心法维护了 `p.combo`（最多 3 层，每层 +15% 伤害），但它只参与数值，界面从不显示。玩家无法知道自己的节奏正在叠加。

### J06 战报里看不到"我有多强" · P1

`combat.js:310` 的 `publicResult` 把 `b.performance` 整个带进战报，而 `core.js:562` 对 `performance` 是**开放的数值字典**校验（正则字段名 + `number(0,CAP)`）。现有字段只有 handled / missed / pills / damageTaken。

也就是说：战报知道"你挨了多少打"，但不知道"你打出了多少"。缺少最高单击、总输出、会心次数、击杀数，无法回答"我这次是不是更强了"。

### J07 稀有战利品没有独立节拍 · P1

初查时我记成「结算是一次性静态列表」，**复核后更正**：`rewards.css:17` 已经有错峰入场——

```
.settlement-card{animation:settlement-card-enter .35s calc(min(var(--reward-order),8)*55ms) ease-out both}
```

列表确实是一件件出现的。真正缺的是**稀有品与普通品没有区别**：`rewards.js:46` 对 `rarity>=4` 只多加了 `settlement-rare` 类，效果仅为底色与内阴影（`rewards.css:18`），没有额外的揭示节拍。

对比抽卡：`app.js:689` 的红卡有 `red-reveal` 全屏法阵与冲击波。同一个游戏里，抽到红装的仪式感远强于打出红装。

### J08 突破没有落差对比 · P1

`app.js:756` 的 `breakthroughResultModal` 是一段文字加一张图。突破是全局最强的成长节点，却不显示攻击、气血、战力具体涨了多少。

### J09 没有成就或称号墙 · P2

全仓库 `成就` 出现 0 次，`称号` 1 次。首通与三星记录存在 `s.progress`，但没有被汇总成可回顾的里程碑。本轮不做。

### J10 三仙阶仍无长篇行动链 · P2

承接 [V4.7 心流评审](FLOW_REVIEW_V4_7.md) 的遗留项。本轮不做，保持为下一轮内容方向。

## 成长曲线的量化背景

`data.js:19-20`：`layerXp=[100,160,240,360,520,740,1000,1340,1740,2200]`，`realmXpFactors=[1,3,8,20,50,125]`。

- 单大境满层修为 = `8400 × factor`，六境合计 **1,738,800**
- 被动修为 `core.js:263`：每 3 秒 `(3+阵+藏经/3+心法/5) × factor`
- 第六境基础值 = `4 × 125 = 500 / 3秒`，即每层 2200×125=275,000 修为约需 **27.5 分钟**纯挂机

结论：**成长速度不是瓶颈，可感知性才是**。数字涨得很快，但玩家在战斗里看不到它涨。这决定了本轮只做呈现层，不动任何数值。

## 本轮取舍

做：J01–J08，全部属于**呈现与信息**，不触碰经济、掉落、敌人强度、经验曲线与存档版本。

不做：J09、J10。它们需要新的系统或大量文本，与"这一轮先把打击感补齐"的目标不同批。

## 约束

1. 不改 `s.version` / `contentVersion`，不改 `ascension.version`。战报指标复用 `performance` 开放字段（`core.js:562` 已支持）。
2. 战斗飘字是**临时呈现**，不进入存档；但为保证存档可校验，`b.feedback` 作为有界字段在 `core.js` 显式校验。
3. 所有新动画必须在 `prefers-reduced-motion: reduce` 下降级为静态（项目既有约定，见 `battle.css:1225`、`rewards.css:55`）。
4. 飘字层挂在**被 patch 的 DOM 树之外**，避免每 250ms 的重渲染打断动画（`app.js:117` 的 keyed patch 会移除未匹配节点）。
